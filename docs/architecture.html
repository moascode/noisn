1

Product Selection

User opens the React UI and selects a pension product. This triggers a Camunda process instance start via the REST API, passing the chosen productCode.

React UI Camunda REST
2

Session Initialisation

The init-session worker runs first, loading product defaults (DANICA_BALANCE or DANICA_LINK) into process variables — contribution limits, risk profiles, payout options.

init-session worker Product defaults
3

Intake Phase (Ad-hoc Subprocess)

Claude drives a conversational loop: ask-question → store-answer. UI polls pendingQuestion every 2 s, user replies, worker parses & stores the typed answer. The assess-sufficiency tool scores completeness (0–100); loop exits when score ≥ 80.

Claude 3.5 Sonnet tool-ask-question tool-store-answer tool-assess-sufficiency
4

Eligibility Check

Before simulation the check-eligibility worker calls POST /eligibility on the Calculator API. Rule-based checks determine which covers (critical illness, life insurance, health modules) are available based on age and employment status.

Calculator API tool-check-eligibility
5

Simulation (Call Activity Subprocess)

The run-simulation worker calls POST /simulate. The Calculator computes: future value of contributions (compound monthly interest), annuity monthly payout, itemised coverage premiums, salary-replacement %, gap to 80% target. Results stored in process variables.

POST /simulate tool-run-simulation
6

Iterate Phase (Ad-hoc Subprocess)

Claude presents results. User explores "what-if" scenarios in plain language. parse-intent classifies each message:

  • CHANGE_PARAMETER → update-parameter → re-run simulation → explain-delta
  • ASK_QUESTION → query-kb (Bedrock Knowledge Base RAG)
  • CONFIRM → exit iterate phase → compile report
Claude 3.5 Sonnet Bedrock KB (RAG) tool-parse-intent tool-update-parameter tool-explain-delta
7

Report Generation & Delivery

compile-report assembles the final dossier from all variables (profile, configuration, full simulation history across all runs). deliver-report sets reportReady=true. UI detects this and switches to the report view — a multi-run comparison with replacement gauge.

compile-report deliver-report React Report View

⚙️

Camunda 8 / Zeebe

Managed cloud · BPMN 2.0 · gRPC
  • Hosts pension-configurator.bpmn process definition
  • Manages process instances; all session state as variables
  • Distributes job tasks to pyzeebe workers via gRPC
  • REST API for UI to read/write variables and send messages
  • Boundary error events for 30-min timeout & agent failures
  • Call activity pattern for reusable simulation subprocess
🔧

Job Workers

workers/ · Python · pyzeebe 4.4
  • 14+ workers subscribing to Zeebe gRPC job stream
  • bedrock_client.py — invoke_llm, invoke_llm_json, query_knowledge_base
  • camunda_client.py — get/set process variables, send messages
  • prompts.py — INTAKE, ITERATE, DELTA, SUFFICIENCY system prompts
  • tools/workers.py — all tool implementations (ask, store, simulate, …)
🤖

AWS Bedrock (Claude)

boto3 · Claude 3.5 Sonnet · Converse API
  • Drives conversational intake — decide what to ask next
  • Scores information sufficiency 0–100 as JSON
  • Parses natural-language intent → structured JSON action
  • Generates delta explanations (plain Danish/English)
  • RetrieveAndGenerate for KB-backed product Q&A
📚

Bedrock Knowledge Base

Bedrock KB · RAG · Vector store
  • Stores DANICA_BALANCE and DANICA_LINK product documentation
  • Queried via RetrieveAndGenerate API (tool-query-kb worker)
  • Grounds AI answers about product features, terms, limits
  • Activated during Iterate phase for ASK_QUESTION intents
🧮

Calculator API

api/ · FastAPI 0.115 · Pydantic 2.9
  • POST /simulate — full pension projection + premium breakdown
  • POST /eligibility — rule-based cover eligibility flags
  • GET /products/{code}/defaults — product configuration defaults
  • Stateless — no persistence, pure calculation functions
  • calculate_pension_amount: FV compound monthly interest
  • calculate_monthly_pension_payout: annuity drawdown at 2%
  • calculate_coverage_premiums: itemised insurance costs
📋

BPMN Process

bpmn/ · pension-configurator.bpmn
  • Start Event → init-session service task
  • Intake Ad-hoc Subprocess (conversational loop)
  • pension-simulation Call Activity (reusable subprocess)
  • Iterate Ad-hoc Subprocess (explore & adjust)
  • compile-report + deliver-report service tasks
  • End Event; boundary: 30-min timer, agent-error escalation
☁️

Infrastructure

Camunda Cloud · AWS · .env
  • ZEEBE_ADDRESS / CLIENT_ID / CLIENT_SECRET → Camunda cluster auth
  • CAMUNDA_REST_URL / TOKEN → REST API for UI & workers
  • AWS_REGION / ACCESS_KEY / SECRET → Bedrock access
  • BEDROCK_MODEL_ID → Claude model selection
  • BEDROCK_KB_ID → Knowledge Base identifier
  • CALCULATOR_API_URL → internal API endpoint for workers

All session state lives in Camunda process variables — no separate database. Workers read and write these atomically.

🔄 State Machine Flow

▸ INIT → defaults loaded
▸ INTAKE → profile variables filled
▸ ELIGIBILITY → flags set
▸ SIMULATING → results written
▸ ITERATING → history grows
▸ REPORT_READY → reportReady=true
