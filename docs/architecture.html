1

Product Selection

User opens React UI and selects pension product. UI sends message via WebSocket to Spring Boot, which triggers a Camunda process instance start with the chosen productCode.

React UI WebSocket/STOMP Camunda REST
2

Session Initialisation

Spring Boot job worker (init-session) runs first via Zeebe gRPC. Loads product defaults (DANICA_BALANCE or DANICA_LINK) into process variables — contribution limits, risk profiles, payout options.

Zeebe Job Spring Worker
3

Intake Phase (AI Agent Sub-process)

Camunda AI Agent Connector calls Claude via AWS Bedrock. Claude drives conversational loop: ask-question → Spring worker stores answer. Connector calls assess_sufficiency tool; loop exits when score ≥ 80. Updates streamed to React via WebSocket.

Claude 3.5 Sonnet AI Agent Sub-process WebSocket push
4

Eligibility Check & Simulation

Spring Boot workers call Calculator API endpoints. Eligibility rules checked; calculators run pension simulation (FV, annuity payout, premiums). Results stored in Camunda process variables. Report summary generated by AI Agent Task.

Spring Calculator Simulation Sub-process
5

Iterate Phase (AI Agent Sub-process)

Claude parses user intent (CHANGE_PARAMETER / ASK_QUESTION / CONFIRM). If parameter change: Spring worker updates variable → re-runs simulation → Claude explains delta via Bedrock. If question: Claude queries Knowledge Base (RAG). Loop continues until confirmation.

Claude 3.5 Sonnet Bedrock KB (RAG) Real-time updates
6

Report Generation & Delivery

Spring Boot worker (compile-report) assembles final dossier from all variables (profile, config, simulation history). Sets reportReady=true. React UI detects via WebSocket and switches to report view with multi-run comparison chart.

compile-report worker React Report View

React UI

ui/ · React 18.3 · Vite 5.4
  • ReplacementGauge — visual % toward 80% salary replacement target
  • SimulationReport — results, costs, config, multi-run comparison
  • ChatBubble — conversation UI with typing animation
  • Product selection screen (DANICA_BALANCE / DANICA_LINK)
  • WebSocket STOMP client for real-time updates
  • Sends user messages via WebSocket to Spring Broker
🔌

Spring WebSocket Broker

Java · Spring Boot · spring-websocket
  • WebSocket endpoint with STOMP protocol for React UI
  • Routes messages to/from Camunda process via REST API
  • Publishes pendingQuestion, simulationResult, reportReady events
  • Real-time push eliminates polling; reduces latency
  • Session management, message queuing, subscription handling
⚙️

Camunda 8 / Zeebe

Managed cloud · BPMN 2.0 · gRPC
  • Hosts pension-configurator.bpmn process definition
  • Manages process instances; all session state as variables
  • Distributes job tasks to Spring Boot workers via gRPC
  • AI Agent Connector calls Bedrock directly (not Spring)
  • REST API for UI and broker to read/write variables
  • Boundary error events for 30-min timeout & failures
🔧

Zeebe Job Workers

Java · camunda-zeebe-spring-boot-starter
  • @ZeebeWorker annotated methods subscribe to Zeebe gRPC stream
  • Tool workers: ask-question, store-answer, check-eligibility, etc.
  • Read process variables, execute logic, write results back
  • Calls Calculator API via REST (not Bedrock)
  • Completes jobs atomically; Zeebe persists state
🤖

AI Agent Connector

Camunda · Bedrock · Claude 3.5
  • Camunda 8 element template (not in Spring Boot)
  • Sub-process variant: multi-turn reasoning loop (intake, iterate)
  • Task variant: single-shot tasks (report summary, delta explanation)
  • Calls AWS Bedrock Converse API directly
  • Native short-term memory within Sub-process connector
  • Tool resolution auto-discovers ad-hoc activities
📚

Bedrock Knowledge Base

AWS · RAG · Vector store
  • Product documentation for DANICA_BALANCE / DANICA_LINK
  • Queried via RetrieveAndGenerate (called by Camunda connector)
  • Hybrid search: semantic + keyword (Titan Embeddings v2)
  • Grounds AI answers about product features, rules, coverage
  • Activated during Iterate phase for ASK_QUESTION intents
🧮

Calculator API

Java · Spring Boot · Spring MVC
  • POST /simulate — full pension projection + premium breakdown
  • POST /eligibility — rule-based cover eligibility flags
  • GET /products/{code}/defaults — product defaults
  • Stateless — no persistence, pure calculation functions
  • calculate_pension_amount: FV compound monthly interest
  • calculate_monthly_pension_payout: annuity drawdown at 2%
📋

BPMN Process

bpmn/ · pension-configurator.bpmn
  • Start Event → init-session service task
  • Intake Ad-hoc Subprocess (AI Agent Sub-process connector)
  • pension-simulation Call Activity (reusable subprocess)
  • Iterate Ad-hoc Subprocess (AI Agent Sub-process connector)
  • compile-report + deliver-report service tasks
  • End Event; boundary: 30-min timer, agent-error escalation
☁️

Infrastructure

Camunda Cloud · AWS · .env
  • ZEEBE_ADDRESS / CLIENT_ID / CLIENT_SECRET — Camunda auth
  • CAMUNDA_REST_URL / TOKEN — REST API for Spring + UI
  • AWS_REGION / ACCESS_KEY / SECRET — for Camunda connector only
  • BEDROCK_MODEL_ID — Claude model selection (in Camunda, not Spring)
  • BEDROCK_KB_ID — Knowledge Base identifier
  • SPRING_DATASOURCE_* — optional DB for extended state (not required)

All session state lives in Camunda process variables — no separate database needed. Workers read and write these atomically via Zeebe.
